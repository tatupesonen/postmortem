## Done

### `crates/pm-text` — text extraction (64 unit tests)
Streaming extractors that push text into a `TextSink` (the sink can stop
extraction: cancellation, limits). `kind_for_mime` follows Autopsy's
`TextExtractorFactory` order (plain text → HTML ≤ 50 MB → SQLite → document
formats Autopsy hands to Tika; octet-stream, x-msdownload, archives and
video excluded). `sniff_mime` gives a coarse MIME when File Type
Identification has not run. `extract()` catches panics from third-party
parsers.

| Module | Covers |
|---|---|
| `encoding` | BOM → UTF-16 NUL-interleave heuristic → valid UTF-8 → `chardetng` over 100 KB; streaming `encoding_rs` decoder |
| `plain` | `text/*`, 64 KiB blocks |
| `strings` | Autopsy's two scanners: English-only (≥ 4 printable, single NUL skipped) and international (UTF-8/UTF-16LE/BE per offset, script locking with Autopsy's own per-code-point table `data/strings_scripts.bin`, generated by `scripts/fixtures/gen-strings-script-table.py` from `StringExtract.properties`); streaming, strings across 1 MiB blocks are not split (Autopsy splits them) |
| `html` | tolerant tokenizer/renderer (blocks → newlines, cells → tabs, entities, `<pre>`), Jericho-style metadata `Scripts/Links/Images/Comments/Others` |
| `xml` | quick-xml walker + generic XML text |
| `office` | DOCX (body, headers, footers, notes, comments, `w:delText`), PPTX (slides, notes), XLSX (shared strings, sheets, cells), ODT/ODS/ODP; core/app/meta properties; per-part and total decompression caps |
| `ole` | Word 97+ piece table (fields: instructions dropped, results kept), Excel BIFF8 (SST with CONTINUE, LABELSST/LABEL/NUMBER/RK/MULRK/STRING), PowerPoint text atoms, Summary/DocumentSummary property sets; encrypted docs reported |
| `rtf` | control-word scanner: destinations, `\'hh` in `\ansicpg`, `\uN` + `\ucN`, `\bin`, `\info` metadata |
| `pdf` | `pdf-extract` page by page (own `OutputDev`, streamed), Info dictionary, PDF dates → UTC; empty-password decryption |
| `email` | RFC 822/MIME: headers, multipart, base64/QP, charsets, RFC 2047 words, HTML parts rendered |
| `sqlite` | Autopsy's exact table-dump format via a temporary copy |
| `chunker` | Autopsy `Chunker` (30 720/31 744/32 760-byte base/window rules on text and lower-cased sizes, NFKC, Solr-invalid chars → `^`), streaming with combining-sequence safety |
| lib | `metadata_block` (Autopsy's METADATA separator), `artifact_text` (`ArtifactTextExtractor`) |

Metadata keys use Tika names (`Author`, `Last-Author`, `Creation-Date`,
`Last-Save-Date`, `Last-Printed`, `Title`, `Company`, `Application-Name`,
`Producer`, …) so the `TSK_METADATA` mapping of inventory 05 §1.4.3 applies.

### `crates/pm-search` — Tantivy indexes, keyword lists, matching (52 unit tests)
* `keywords`: built-in locked lists with Autopsy's exact regexes (phone, IP,
  e-mail, URL, CCN; `use_for_ingest=false`), default enabled lists, Autopsy
  `keywords.xml` import/export (BOM, defaults, export omits ingest flags),
  EnCase import (UTF-16, tree from child counts, `parent/child` names,
  `(2)` suffixes, GREP skipped). `java_regex` maps Java's `\<`/`\>`.
* `ccn`: `is_valid_ccn` (separators, IIN length table with "last insert
  wins", grouping, Luhn incl. all-zero rule), CCN hit filter (regions
  len…12), track 1/2 parsing, BIN database from a binlist `ranges.csv`.
* `matcher`: inline search compiled once per job (Aho-Corasick literal
  pre-filter + `RegexSet`), exact/substring/regex semantics, phone/IP
  trimming with one-char step-back, e-mail ≥ 8 chars + IANA TLD
  (`data/tlds-alpha-by-domain.txt`), CCN validation, per-chunk dedupe,
  Autopsy snippet format; invalid regexes reported.
* `plan`: trigram formula from literals/regexes (regex-syntax HIR),
  property-tested to never exclude a real match.
* `content::ContentIndex`: `<case>/Index/content`; chunk docs + per-object
  summary doc (chunk 0: name/label + chunk count); `text` words with
  positions (CJK per ideograph, no stop words), `tri` trigrams, stored
  chunk text; exact (phrase), substring (trigrams; regex over the trigram
  dictionary for 1–2 chars) and regex (planned trigrams, else scan)
  searches verified against stored text; overlap hits left to the next
  chunk; one row per object with preview/terms; `object_hits` for viewer
  hit navigation; `num_chunks`, `chunk`, `stats`; data-source filter and
  deletion; periodic commits (`maybe_commit`), shared writer.
* `names::NameIndex`: `<case>/Index/names`; positional trigrams on name and
  full path → substring = phrase query at fixed offsets (exact, no scan);
  1–2 chars via trigram-dictionary regex; exact/prefix on names; filters
  (data source, deleted, dirs, extension, size); keyset paging by file id;
  `catch_up(db)` indexes files above the last indexed id (commit payload),
  committing every 1 M names; `add` for derived files.
* `CaseIndex::open(case_dir)`: one shared instance per case per process;
  schema-version file wipes stale indexes.

## Decisions / deviations from Autopsy
* CCN IIN table keeps Autopsy's `{16,17,18,29}` typo (parity; Autopsy's
  own test vectors pass). The Autopsy CCN regex's lazy separator means a
  space/dash-separated card number only matches its first 12 digits (Java
  and Rust agree) — kept for parity, covered by a test.
* BIN database: binlist `ranges.csv` has no licence, so it is not bundled;
  it is loaded from a user-supplied path. Autopsy pads a blank `iin_end`
  from the already 0-padded start, so 6-digit BINs only match `XXXXXX00`;
  postmortem pads the end with 9s (fix).
* Exact-match phrase matching re-examines tokens after a partial mismatch
  (Autopsy bug fixed). No English stop words in the index.
* Regexes use Rust `regex` syntax (no look-around/back-references) for both
  inline and ad-hoc search; invalid ones are reported, not silently dropped.
* Lower casing is locale-independent (Autopsy uses the JVM default locale).
